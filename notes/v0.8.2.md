# CARIX 0.8.2

Üretim kanalı: **stable**. Hedef dağıtım paketi: `CARIX-Setup-v0.8.2.exe`.

## Düzeltmeler ve SCM İyileştirmeleri

### Windows PowerShell 5.1 `sc.exe` Parametre Düzeltmesi
- `install.ps1` ve kurucu betiğinde `sc.exe config` ve `sc.exe create` komutlarında Windows PowerShell 5.1 ortamında hatalı ayrışan birleşik `"binPath= value"` parametresi ayrıldı; `binPath=` seçeneği ve yürütülebilir dosya yolu iki bağımsız argüman olarak iletildi.
- Boşluk içeren yürütülebilir servis yolları için tırnaklama kuralları düzeltildi: API servis yolu üçlü tırnaklama (`"""..."""`) ile korundu, PostgreSQL servis parametreleri ters eğik çizgi (`\"`) ile kaçışlandı.

### Fail-Closed ve Hata Durumunda Açık Başarısızlık (No False Success)
- SCM servis kaydı, yapılandırması veya servis başlatma adımlarında oluşan native ve `sc.exe` hatalarının yalnızca uyarı verilerek sessizce başarılı sayılması engellendi.
- Hata anında kurulum işlemi derhal kesilir (`throw`), işlem günlüğüne (`operations/journal.json`) başarısızlık (`failed journal`) açık hata koduyla kaydedilir; gerçeğe aykırı başarı durumu üretilmez.

### Mevcut PostgreSQL Servisinin Korunması (Preserve Existing PG Service)
- Kurulum ve güncelleme sırasında mevcut `CarixPostgres` servis kaydının gereksiz şekilde kaldırılması (`unregister`) engellendi; mevcut kayıtlı PostgreSQL servisi korunacak ve doğrudan yapılandırılacak şekilde entegre edildi.

### Visual C++ Yeniden Dağıtılabilir Paket Önkoşulu (Temiz Windows Kurulumu)
- Temiz Windows ortamında PostgreSQL `initdb.exe` çağrısının eksik C++ çalışma zamanı nedeniyle çökmesini (`0xC0000135` / VCRUNTIME140) önlemek için resmi Microsoft Visual C++ 2015-2022 x64 Redistributable (v14.42.34433.0) paketi tek dağıtılabilir kurucu içine gömüldü.
- Veritabanı başlatma adımı öncesinde sessiz modda (`/install /quiet /norestart`) önkoşul kurulumu sağlanarak harici bağımlılık ihtiyacı ortadan kaldırıldı.

### Yükseltme Sırasında PostgreSQL Port Tahliye Yarışı (Bounded Listener Drain)
- Sürüm yükseltmelerinde `CarixPostgres` servisi durdurulduktan sonra soket ve dinleyici tahliyesinin 2-4 saniye gecikmesi nedeniyle oluşan sahte port çakışması giderildi.
- Kurucuya ait durdurulan servisler için 15 saniyeye kadar sınırlı port tahliye beklemesi (`Wait-InstallerPortDrain`) eklendi; yabancı/üçüncü parti port çakışması koruması ve SCM durdurma doğrulaması korundu.

## Kesinti İncelemesi ve Gözlemler

- Kaynak metadata incelemelerinde, önceki kurulum denemesinde SCM servis yollarının güncellenememesi ve tırnaksız eski yollarda kalması gözlemlenen servis kesintisine yol açmıştır.
- `CarixUpdateController` servisinin durma (SCM Event ID 7034 / Hata Kodu 1067) mekanizması salt okunur sistem kayıtlarından kesin olarak kanıtlanamamıştır.

## Doğrulama ve Windows Kabul Sonuçları

- **Windows Sandbox Canlı Kabulü (PASSED):** `IsolatedWindowsAcceptance` tarafından Windows Sandbox ortamında iki kritik senaryo test edilmiş ve onaylanmıştır:
  - **Temiz Kurulum (Senaryo B):** Harici hiçbir C++ çalışma zamanı bulunmayan saf Windows ortamında tek dağıtılabilir `CARIX-Setup-v0.8.2.exe` çalıştırılmış, gömülü VC++ redistributable paketi sessizce yüklenmiş, PostgreSQL `initdb.exe` hatasız tamamlanmış, tüm 3 servis (`CarixPostgres`, `CarixServer`, `CarixUpdateController`) tırnaklı yollarla `Running` durumuna geçmiş ve API `http://127.0.0.1:8443/api/health` üzerinden HTTP 200 (`ready: true`, `maintenance: false`) yanıtı vermiştir.
  - **Yükseltme ve Veri Korunumu (Senaryo A):** 0.8.1 sürümünden 0.8.2 sürümüne tam NSIS yükseltmesi gerçekleştirilmiş, servis durdurulması sonrası port dinleyici tahliyesi başarıyla beklenmiş, önceden tohumlanan iş verisi (`CarixPreUpgradeBaseline081`) korunmuş ve yeniden başlatma sonrası kalıcılık kanıtlanmıştır.
